3D 运营管理系统 对外接口（API v1）

以后接 Lazada / Shopee / TikTok 开放平台、BigSeller 自动化，或者自己写脚本，都用这套接口把订单送进系统。 送进来的订单和表格导入一样：自动对上产品 SKU、生成生产任务、计入利润和耗材计划。

地址：{{BASE}}/api/v1/...（局域网里用 NAS 的 IP，例如 http://192.168.31.200:8790/api/v1/ping）
认证：在「账号」页 → 「API 与店铺对接」创建 API 密钥，请求头带 Authorization: Bearer lh_xxxx（或 X-API-Key: lh_xxxx）。
格式：请求和返回都是 JSON（UTF-8）。返回里 ok 为 false 时看 error。

GET/api/v1/ping

测试密钥和网络是否正常。

curl -H "Authorization: Bearer lh_xxxx" {{BASE}}/api/v1/ping
→ {"ok": true, "version": "2.55.0", "time": 1791200000}

POST/api/v1/orders　推送订单（新增或更新）

平台 + 订单号相同视为同一个订单：再次推送只更新状态等信息，不会重复，也不会覆盖你在系统里写的定制备注和加急。 已经开始生产的订单，商品明细不会再改。一次最多 1000 个订单。

{

  "platform": "lazada",             // 可选，订单里没写平台时用这个
  "orders": [{
    "platform": "lazada",           // lazada / shopee / tiktok / 其他
    "shop": "My3DShop",
    "order_no": "26100512345",      // 必填
    "status": "to_ship",            // 见下面「状态」，也可以直接传平台原文（如 READY_TO_SHIP、待发货）
    "order_time": "2026-10-05T10:00:00+07:00",   // Unix 秒 / 毫秒 / ISO / "2026-10-05 10:00"（支持佛历）
    "ship_by": 1791300000,
    "buyer": "Somchai",
    "buyer_note": "ขอสีชมพูเข้มๆ",
    "seller_note": "",
    "order_total": 258,
    "shipping_fee": 0,
    "platform_fee": 15.5,           // 平台佣金/手续费；不传就按设置里的扣点估算

    "payment": "COD",               // 货到付款填 COD（或 cod 金额 > 0）；会用于审单和拒收风险

→ {"ok": true, "orders_new": 1, "orders_updated": 0, "items": 1,
   "unmatched": [], "skipped_items_locked": 0, "errors": [], "jobs": {"created": 1, "cancelled": 0}}

unmatched：产品库里找不到的 SKU（不会生成生产任务）。errors：格式不对、被跳过的订单。 held（v2.11）：新订单里命中审单规则、被挂起到「待审核」的个数——挂起的订单要在 ERP 里人工审核通过后才排产。

状态

status含义会不会生产
unpaid未付款不会
to_ship待发货会（自动生成打印任务）
shipped已发货不会
completed已完成不会
cancelled已取消（还没开始打印的任务会自动删除）不会
returned退货/退款不会
delivery_failed拒收 / 派送失败（v2.11 新增；平台原文如 Failed Delivery、Package Returned、拒收 会自动识别）。会自动登记一条售后等包裹退回验货不会
quote报价/预订单会排产估算，不计收入

GET/api/v1/orders　查询订单

参数：since（Unix 秒，按更新时间，只返回之后有变化的），status，platform，limit（最多 1000）。 返回订单、商品明细和生产进度（jobs）。v2.9.1 起每个订单多一个 cost：本系统算的收入、平台费、材料、机时、包材、失败损耗和利润。 用只读密钥查询时，不返回买家姓名、收件人、电话、地址、邮编、买家留言、买家识别码。

v2.11 新增字段（只加不改）：hold（1 = 挂起待审核，不排产）、hold_reason、reviewed_at / reviewed_by、 payment（cod = 货到付款）、ship_method（pickup 上门揽收 / dropoff 送到网点 / self）、 handover_id（发货交接单号）、buyer_key（同一买家的识别码，只读密钥不返回）， 金额拆分 item_amount、buyer_shipping、platform_discount、seller_discount、commission、service_fee、payment_fee、settlement（没有就是 null）。 status 多了一个值 delivery_failed。 cost 里多了 fee_source（平台费怎么来的：settlement = 订单金额 − 结算到账；detail = 佣金 + 服务费 + 支付手续费 + 卖家优惠；import = 导入的平台费；estimate = 按扣点估算）和 fee_detail。

GET /api/v1/orders?since=1791200000&status=to_ship

POST/api/v1/labels/import　上传平台面单 PDF（v2.35）

浏览器扩展用（员工在卖家中心 / BigSeller 下载面单 PDF 时，点「发送」才传上来），自动化工具也可以用。表单上传（multipart）： file = 面单 PDF，site = 从哪个网站下载的（可不填，只记日志）。系统按每页上的订单号 / 运单号拆开、对应到订单（最近 90 天、没取消的）。

→ {"ok": true, "pages": 12, "matched": 11, "unmatched_pages": [7], "order_nos": ["2410090001", "…"], "hint": "…"}

GET/api/v1/skus　产品 SKU 列表

所有产品变体的 SKU、颜色、克数、打印时长。v2.9.1 起还返回：材质、售价（最终价 / 建议价 / 最低价）、单件成本拆分 unit_cost、 预估包裹重量 est_package_weight_g（v2.55.1 起按规格的实物数据：净重 + 纸箱 + 填充物；没有净重时 = 克数 + 包材重量）、包裹尺寸 （v2.55.1 起每个规格自己的；physical_confirmed = 尺寸 / 净重 / 包裹尺寸 / 包裹重量都已人工确认）、Lazada / Shopee 类目、导出时间。 参数 since（Unix 秒）：只返回之后改过的产品。

每条都有 product_id（产品编号，如 3DP0012）和 updated_at（产品最后修改时间，Unix 秒；改资料、改上架状态都会变）。 v2.12.1 起多 variant（规格中文名，和 spec 一样；没有规格为空）。v2.12 起多返回：product_code（和 product_id 一样）、draft（选品 / 采集建的、还没填颜色的草稿为 true）、 source（选品来的产品的来源信息，其他为 null）。 数据多时用 since 分段拉：按 updated_at 记住拉到哪里，往回多拉 10 分钟。

v2.11.1 新增 listing（每个 SKU 都带，同一产品的 SKU 一样），按平台分 lazada / shopee，状态按平台自己的商品状态：

status含义Lazada 后台Shopee 后台
none未导出——
pending已导出表格，还没上传——
failed上传表格时报错，平台上没生成商品批量上传失败批量上传失败
uploaded已上传，平台审核中Pending QC审核中
rejected平台审核不通过 / 违规QC Rejected违规 / 禁止
live审核通过、在售Active在售 Live
inactive平台上已下架Inactive已下架 Unlisted
update平台上已有，ERP 资料改过还没同步（看 platform_status 知道平台上现在是什么状态）—
"listing": {
  "lazada": {"status": "live", "platform_status": "live",
             "first_uploaded_at": 1791200000,   // 第一次上传到平台
             "last_uploaded_at": 1791200000,    // 最近一次上传
             "first_listed_at": 1791290000,     // 第一次审核通过、在售（测款期从这里算；还没上线过为 null）
             "live_at": 1791290000,             // 最近一次变成在售
             "delisted_at": null,               // 最近一次在平台下架

             "batch_id": 3, "batch": "Lazada 10-05 第 1 批", "note": null},
  "shopee": {"status": "none", ...}
}

状态是人在 ERP 里按平台后台标记的（导出页 / 上架批次），时间是标记的时间。上架状态变化会更新产品的 updated_at，用 since 增量能拉到。 2.11.1 以前标成「已上传」的，first_uploaded_at 用当时标记的时间，first_listed_at 为 null（不知道哪天过审）。

v2.32.1 GET /api/v1/skus 新字段 image（商品主图，没有图为 null）： {"id": "3DP0012-a1b2c3d4e5", "url": "/api/v1/images/3DP0012-a1b2c3d4e5", "updated_at": 1791300000, "for": "sku"}。 for = sku：这个 SKU（颜色 / 规格）自己选的图；product：产品封面（图片顺序第 1 张）。 图片编号稳定不变，换图、重新处理图片编号就变；改图会更新产品 updated_at，按 since 增量能拉到。

GET/api/v1/images/<图片编号>[?size=thumb]　商品图片（v2.32.1，只读密钥）

返回图片文件（image/jpeg 或 image/png）。size=thumb：长边 ≤ 400px 的小图；不带返回原图。 带 ETag 和 Last-Modified，重复拉时带 If-None-Match / If-Modified-Since 返回 304。 编号不存在或不合法（例如 ../）：404 {"ok": false, "code": "not_found"}。只能取产品资料里登记的图片，不能读其他文件。

GET/api/v1/cost-params　成本参数（v2.9.1）

设置页里的成本、扣点、加价率、包材、打印机列表（编码、机型、是否启用）、每天可用打印小时、颜色代码表。不含任何密钥。 外部系统算成本和利润时用这一套数，保证两边口径一致。

GET/api/v1/profit　利润报表（v2.9.1）

和「利润」页一样：每日、按 SKU、按平台的收入和利润。参数 days（默认 30，最多 366）。

只读密钥（v2.9.1）

创建密钥时勾选「只读」：只能用 GET 查询，不能推送订单、改状态，也不能调用客服接口；查询订单时不返回买家个人信息。 给运营分析系统等只需要看数据的程序用这种密钥。

运营写回（v2.10，对接规范 v1.1 第 6 条）

用「运营写回」权限的密钥（scope = ops）调用；这种密钥只能调 /api/v1/ops/... 和 /api/v1/ping。 能改：泰文标题 title_th、类目属性 attributes、售价 price、上下架 active。 硬性限制：售价不能低于该 SKU 的 floor_price；每个 SKU 每天（泰国时间）最多改 1 次售价；不能删除产品，只能下架；标题 10–255 个字符。 ERP 设置「写回方式」为 auto（默认）时直接生效，为 confirm 时记成「待确认」，人工通过后才生效。改过的产品在导出页标「有修改待同步」。

POST/api/v1/ops/products/<SKU 或 产品编号>

{"changes": {"title_th": "...", "attributes": {"catProperty.p-20000": "No Brand"}, "price": 299, "active": false},
 "reason": "测款期点击率低于同类，换标题关键词", "source_action_id": "A-20261020-001"}
→ {"ok": true, "change_id": 123, "applied": true, "status": "applied", "product_id": "3DP0001", "sku": "3DP0001-WH",
   "before": {"price": 259, ...}, "after": {"price": 299, ...}}
被拦下时（HTTP 400）：{"ok": false, "error": "售价低于最低价 179", "code": "below_floor"}

错误代码 code：below_floor 低于最低价、price_daily_limit 今天已改过价、sku_required 多 SKU 产品改价要用 SKU、 title_length 标题长度不对、invalid_field 不支持的字段、invalid 格式不对、not_found（404）找不到产品 / SKU。 price 只能用 SKU 调用（单 SKU 产品也可以用产品编号）；标题、属性、上下架是产品级的。一次调用的几个字段要么全部生效，要么都不生效。

POST/api/v1/ops/changes/<change_id>/revert　撤回

恢复成改之前的值（「待确认」的会变成「已拒绝」）。返回 {"ok": true, "change": {...}}。

GET/api/v1/ops/changes?since=&status=&limit=　写入记录

按更新时间返回：id, ts, product_id, sku, requested, before, after, reason, source_action_id, status（applied 已生效 / pending 待确认 / rejected 已拒绝 / reverted 已撤回）, decided_by, decided_at。也返回当前写回方式 mode。

GET/api/v1/production　生产概况

每台打印机的排队任务数和小时数、待打包、待发货数量。

GET/api/v1/materials　耗材库存与采购建议

每个材料 + 颜色一行：库存公斤、待打印还要多少、每天用量、还能用几天、最晚下单日、建议买几卷。 v2.12 起每行多 spools：{"sealed": 未开封卷数, "open": 已开封在库卷数, "loaded": 在机上卷数, "on": [{"code","printer","slot","remaining_g"}]}； 返回里多 alerts：[{"level": "bad"/"warn", "key": [材料, 颜色], "printer": 机器编码（有时）, "text": 中文提醒}]。

类目

只读、完整密钥都可以调。返回 ERP 里能用的类目（已上传 Lazada 模板的类目，导出上架表格要用），推送时 category 填 name（也接受 id 或 lazada_cat_id）。 另外返回 ERP 的产品分组 groups（参考用）。

 "groups": [{"id": 1, "name": "猫咪系列"}]}

批发站密钥（scope = wholesale，v2.36）

给批发网站用。只能调：GET /api/v1/ping、GET /api/v1/skus、GET /api/v1/images/…（商品图片）、GET /api/v1/orders、POST /api/v1/orders、POST /api/v1/orders/status。 推送和改状态时平台一律当作 wholesale（传别的平台也会被改掉），所以碰不到 Lazada / Shopee 的订单；查询只返回批发订单。 SKU 不返回成本、底价、建议价、手填价、机时；订单不返回成本利润和平台费。批发订单和其他订单一样生成生产任务、占用耗材库存。其他接口一律 403。

AI 接待密钥（scope = chat，v2.38）

给「AI 接待成交系统」（系统一 ai-sales-desk，LINE / Facebook 聊天成交）用。权限和批发站密钥一样窄：只能调 GET /api/v1/ping、GET /api/v1/skus、GET /api/v1/images/…、GET /api/v1/orders、POST /api/v1/orders、POST /api/v1/orders/status。 推送和改状态时平台一律当作 chat，碰不到 Lazada / Shopee / 批发站的订单；查询只返回 chat 订单（含自己客户的收货信息，发货用）。 SKU 不返回成本、底价、建议价、手填价、机时；订单不返回成本利润和平台费。聊天订单和其他订单一样生成生产任务、占用耗材库存。其他接口一律 403。

POST/api/v1/wholesale/hook　登记回调地址（v2.37）

POST /api/v1/wholesale/hook
{"url": "https://shop.example.com/erp/hook/", "secret": "至少 16 位的随机字符串"}

只限批发站密钥。登记后批发订单状态一变，ERP 就 POST 到这个地址：内容 {"event": "order.status", "order_no": "…", "status": "shipped", "time": …}， 请求头 X-Timestamp（Unix 秒）和 X-Signature = HMAC-SHA256(secret, 时间戳 + "." + 请求内容) 的十六进制。网站验签后自己调 GET /api/v1/orders 取最新状态。

GET/api/v1/finance/events　财务事件（v2.18）

「财务」密钥（scope = finance）。库存 / 采购里跟钱有关的事：purchase_payment 采购付款、purchase_received 采购到货入库。参数 since（Unix 秒）、kind、limit（最多 5000）。 字段：id, ts, day, source, kind, amount, currency, category, ref_type, ref_no, method, note, username。

GET/api/v1/finance/inventory?month=YYYY-MM　库存月汇总（v2.18）

这个月库存消耗（按分类 / 类型，按加权平均价）、到货入库金额、采购付款、现在各分类的库存金额。详见对接规范第 11 条。

GET/api/v1/finance/pl · breakdown · cashflow · expenses · tax　财务报表（v2.21）

「财务」密钥，只读。期间：month=YYYY-MM 或 start=YYYY-MM-DD&end=YYYY-MM-DD。pl 损益表；breakdown?by=platform|shop|product|sku|day|month 利润分析； cashflow 现金流；expenses 收支明细；tax VAT 和平台代扣税。字段和口径见对接规范 11.1。

POST/api/v1/webhook/<平台>　平台主动推送

给平台开放后台填的「推送地址（Push URL）」，例如 https://你的域名/api/v1/webhook/shopee。 不用 API 密钥，由平台签名验证。所有推送内容都会记录在「API 与店铺对接」页面，方便联调。 注意：平台推送需要公网能访问到这台 NAS（需要域名/内网穿透），只在局域网里时用定时拉取就够了。

店铺自动导入（定时拉取）

在「账号」页 → 「API 与店铺对接」添加店铺，填开放平台的授权信息并启用，系统每隔设定的分钟数自动拉一次订单（第一次拉最近 7 天）。

平台状态需要
Lazada已写好，待联调Lazada 开放平台 App Key / App Secret + 店铺授权
Shopee已写好，待联调Shopee 开放平台 Partner ID / Partner Key + 店铺授权
TikTok Shop预留TikTok Shop Partner Center 开发者应用
BigSeller预留没有公开接口：用表格导入，或用自动化工具调用 POST /api/v1/orders

Python 示例

import requests
API = "{{BASE}}/api/v1"
H = {"Authorization": "Bearer lh_xxxx"}
r = requests.post(API + "/orders", headers=H, json={"orders": [{
    "platform": "tiktok", "order_no": "TT001", "status": "to_ship",
    "items": [{"sku": "3DP0001-PK", "qty": 1, "unit_price": 129}]}]})
print(r.json())
