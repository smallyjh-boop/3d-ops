# 选品（curate）

把原来单独的「3D选品工具」并进 ERP。**只做 ERP 没有的那部分：在模型网站上找能卖的模型。**
「采用」以后就是 ERP 的产品草稿，之后全用 ERP 自己的功能：产品编辑页（图片 / 修图、规格与变体、文案与 SEO、类目属性、定价）、
模型库（文件分析、切片）、上架检查（许可没核验不能导出 / 推送）、账号、备份、升级、语言。

页面：顶部「商品」菜单的第一个 **选品**（商品 = 选品 · 产品库 · 上架），页面头一排大按钮：**＋ 贴链接采集**、**🧩 打开模型站去采集 ▾**（MakerWorld / Printables / Thingiverse 搜索页，新标签页打开）、⟳ 刷新；
没有在线的扩展、队列里又有在等的，页面上面提醒「没有在线的扩展，采集队列不会动」。四个页签：

| 页签 | 页面 id | 内容 |
|---|---|---|
| 候选池 | `cur_cand` | 模型网站列表页上看到的模型 + 推荐分（六项加权）+ 泰国排除规则 + AI 判断；对上爆款雷达关键词时显示泰国市场的需求 / 价格 / 结果数（没完全对上时按 AI 的泰文搜索词 / 类目找「相近：…」，ERP 没有雷达数据时「去雷达查」）；「采用」；勾选后浮动条：采用所选 / 忽略所选 / 重新读取；「采集可能出错」的可以重新读取或批量删除 |
| 采集箱 | `cur_inbox` | 采用 / 采集的产品草稿先放这里（不进产品库）：左边文件夹（全部 · 按类目 · 未分类 · 自己建的文件夹 = 产品分组），每个产品的状态（文件 / 文案 / 许可 / 图片）和操作（编辑、⬇ 下载模型文件、核验许可、移到文件夹、转入产品库、删除）；勾选后浮动条批量做 |
| 采集队列 | `cur_queue` | 采用后等扩展读详情页的、文件下载进度、最近采用的产品草稿（许可、图片、3D 模型、规格、文案到了没有）；每个产品「⬇ 下载模型文件」「⬆ 手动上传」、下载状态（等扩展 / 下载中 / 已下载 N 个 / 失败原因）、扩展在不在线 |
| 关注巡逻 | `cur_watch` | 关注设计师 / 关键词 / 搜索链接，各网站的节奏和暂停，巡逻记录 |

老板和上架客服能用（上架客服看不到成本、利润、估计售价——接口里就去掉了）。生产看不到。

## 流程

1. **候选**：浏览器扩展在 MakerWorld / Printables / Thingiverse 的列表页读每张卡片（标题、图、下载 / 点赞 / 打印数），
   交给 ERP 打分（`cand.py`）：先按规则（`rules.py`：类目先验、热度、排除规则），后台再让 AI 按泰国电商一次判断 20 个
   （需求、时长 / 克数估算、单色、零件数、售价区间、竞争、泰文搜索词）。利润用 ERP 的成本（`core/pricing`）。
   排除：儿童玩具（TISI）、宗教造型、类似武器、接触食物、成人用品、品牌 / 动漫角色、需要多色、打印太久（上限在设置里）。
2. **采用**（候选池按钮，或模型网站上扩展的「＋采集」）：`adopt.adopt` 马上建 ERP 产品草稿——品名 = 原站标题、来源（原站链接、作者、网站）、
   `license_check = {status: "pending"}`、标题里有品牌 / 动漫词就 `ip_risk` 待确认；详情页进采集队列。
3. **详情页**：扩展在后台标签页打开、按站点包读出描述、标签、许可证、图片、文件链接（`cur_extract.js`）→ `adopt.enrich` 补进草稿：
   原站描述（去掉作者宣传、外链）、许可证初判（`rules.classify_license`，只是初判）、图片（后台下载进产品图片）、模型文件（排队让扩展下载）。
4. **模型文件**：扩展用这台电脑浏览器里原站的登录状态下载，上传到 `/api/v1/curate/ext/files/<id>/upload`，
   **直接存进产品的 `source_files`（模型库），只存一份**。
5. **整理**（文件都到了以后，`adopt.post_process`，后台）：ERP 模型库分析（尺寸、体积、估算克数 / 时长；切好的 3MF 读切片数据）、
   第一个 STL / 3MF 设成 3D 模型、从文件名识别规格（`variants.py`：尺寸、版本、套装，共用零件算进每个规格）建 ERP 规格和变体
   （颜色在编辑页加，加颜色时 规格 × 颜色 展开）、有 AI 时用 ERP 的 AI 文案补全空着的文案字段（`core/ai_copy.complete_copy`）。
   已经有人改过变体的不自动改，只记一条建议。
6. **许可核验**（ERP 这边）：产品编辑页上面和产品 360 有「许可待核验」和「核验通过」按钮（`POST /api/products/<编号>/license`）。
   上架检查（`core/copyrules.problems`，Lazada / Shopee 导出、Lazada 接口推送都用）里许可待核验是**错误**，挡导出和推送。
   系统初判「禁止商用」的要选「仍然核验通过（已买授权）」才能过。核验记在操作日志里。
7. **校准**（`pipeline.calibrate`，后台每 10 分钟）：列表页 AI 估算的时长 / 克数 vs 实测——ERP 生产记录里打完的打印批次
   （开始到结束 ÷ 件数）优先，没有就用切片文件 / 产品变体的克数时长。至少 5 个样本才校准（实测 ÷ 估算的中位数，夹在 0.5–3），
   系数变了候选池全部重算。

上架检查里另外加了选品工具原来的文案规则（**所有产品都用，只是提醒**）：品牌 / 动漫角色词、标题和规格名里的颜色词、营销词、
需要证明的功能说法、泰国敏感品类。词表在 `core/copyrules.py`，选品打分也用同一份。

## v2.50.1 补充

- **采集箱**（`inbox.py`）：`adopt` 建的草稿带 `inbox: true`，产品库（`GET /api/products` 默认不含，`?inbox=all` / `?inbox=1`）、分组数、全局搜索（只有输完整编号才找出来）都不算；
  产品库筛选行有「📥 采集箱 N」。「转入产品库」去掉 `inbox`，许可没核验 / 没模型文件 / 还在用原站图片只提醒（导出 / 推送的许可门槛照旧）。删除 = 删产品草稿，候选标「已忽略」。
  升级时（模块启动、第一次打开选品）已经在产品库里、没导出 / 上架过的选品草稿搬进采集箱，只做一次（`cur_settings.inbox_migrated`）。接口：`GET /api/cur/inbox`、`POST /api/cur/inbox/action`（to_library / delete / copy / download）。
- **下载模型文件**：`POST /api/cur/products/<编号>/download` 没失败也能用——没下载的 / 失败的排队；一个文件链接都还没有就让扩展重新读详情页（读到后自动下载）；都下载过了也重读一次（原站加了新文件）。
  采集队列、产品编辑页（来源卡片 + ③ 3D 模型的占位块）、产品 360、扩展的模型详情页（已采用的模型：「⬇ 下载模型文件到 ERP」，`POST /api/v1/curate/ext/download`）都有这个按钮。
  「手动上传」`POST /api/cur/products/<编号>/upload`：进产品的 `source_files`，和扩展上传的一样做 ERP 分析（不等还在排队的原站下载），第一个 STL / 3MF 当 3D 模型；编辑页自动刷新预览。
  文件列表 `GET /api/cur/products/<编号>/files`，删除 `POST …/files/delete`（挪到 model_history，以后还能从原站再下载）。
- **扩展在不在线**：扩展来领活（`/ext/next`、`/files/next`、`/watch/next`，每分钟一次）就记在 `cur_settings.ext_seen`，3 分钟内有就算在线（`watch.ext_status`）。不在线时按钮旁边提醒「要有一台装了扩展、登录了原站的 Chrome 开着」。
- **采用后马上写 AI 文案**（`adopt.write_copy`，后台）：不等模型文件；详情页最多等 90 秒（`COPY_WAIT_DETAIL`），没开扩展就按原站标题写。只填空着的字段（`core/ai_copy.complete_copy`）。
  只按标题写的、之后没人改过（`source.ai_copy_sig`）的，详情页到了按描述 / 标签重写一次；人改过的永远不自动改。文件分析以后只补克数 / 时长 / 规格（新规格要的泰文选项名空着才补）。
- **原站图片**：下载进产品的图片记 `from: "source"`、`source_url`、`source_site`；编辑页图片区提醒「原站图片，可能有水印……」、每张标「原站图」；上架检查（`core/copyrules.problems`）提醒「还在用原站图片」（修过图的不算）。
- **列表页读卡片**（扩展 3.1.1，`cur_sites.js` `readCard / listCards`，站点包里的 `list`：title / image 选择器、`author_link`、`avatar`、`model_image`）：
  卡片 = 包住一个模型链接的最大的块，作者那一块（`/@用户` 链接、头像、作者名）不算；以前取「第一行字 + 第一张图」，Printables / Thingiverse 的卡片作者在最上面，就读成了作者名 + 头像。
  服务器另外有一道检查（`cand.capture_check`）：标题 = 作者名、缩略图是头像 / 标志 / 太小、Printables 的图不是 `/media/prints/` → 标「采集可能出错」，不交给 AI；已经存着正确资料的不会被读错的覆盖。
  「重新读取」（`POST /api/cur/candidates/recollect`）把候选的详情页排进采集队列（`kind=refresh`，不建产品），扩展读到后改正标题、作者、图；「删除采集错误的」`POST /api/cur/candidates/delete-bad`。
- **泰国市场**（`demand.matcher`）：没完全对上雷达关键词时，按 AI 给的泰文搜索词、AI 类目（`CATEGORY_HINTS`）找最像的雷达关键词，显示「相近：…」；ERP 一个雷达关键词都没有时显示「去雷达查」。

## 关注巡逻和防风控（`watch.py`）

- 关注设计师主页、关键词（站点包里的搜索地址）、搜索链接。扩展每分钟问一次 `/watch/next`，在后台标签页打开列表页、往下翻几屏、读卡片交回。
  第一次只记下已有的，之后新出现的才算「新品」，打分进候选池；高分新品进今日待办（🔔），可选推到手机（运营模块的 LINE / Telegram 提醒）。
- 节奏（从选品工具的 pace.py 搬过来）：页面之间、文件之间、产品之间随机停；每个网站每小时下载有上限、每天巡逻有上限；
  遇到 429 / 403 / 人机验证 / 请求太频繁，这个网站减速一半并暂停 30 分钟（6 小时内再出现暂停 2 小时），采集、下载、巡逻一起停；
  顺利时慢慢提回原来的速度。规则判断不了的失败页面，有 AI 时交给 AI 看。速度档位在设置里（slow / normal / fast）。

## 爆款雷达 ↔ 选品

- 运营 → 市场与竞争 → 找新品（爆款雷达）每个关键词有「去模型站找」：把泰文关键词翻成英文搜索词（有 AI 时），
  每个模型网站建一个关键词关注，然后打开「商品 → 选品 → 关注巡逻」。
- 候选卡片的标题或 AI 给的泰文搜索词里有雷达关键词时，显示那个词的机会分、前 10 日销、结果数、到手价中位、竞品数（`demand.py`，
  通过 `modules.public("ops").market_keywords()`，运营模块关着就不显示）。

## 法律提醒

- **转成产品前必须有人核验许可证**（打开原站看清楚：CC BY 要署名、NC / 标准数字文件许可 / 保留所有权利都不能商用）。系统的初判只是参考。
- 品牌、动漫、游戏角色的造型即使许可证写可以商用也有侵权风险（`ip_risk` 待确认挡导出）。
- **上架尽量用自己打印、自己拍的图**；原站图片可能有版权，只当参考，在编辑页换成自己的图。
