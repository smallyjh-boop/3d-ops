# 模块：拍照识别（recog）——拍照找产品 / 拍照读文字

很多产品没有条码：员工用手机拍一下实物，系统找出是哪个产品 / SKU；货位没有条码、条码坏了：拍货位牌 / 面单，读出上面的字。
认出来的码**像扫码一样**送给当前页面（验货、库存、货位、查订单都不用改）。

## 在哪用

- **手机页 /m**（浏览器和安卓 App）：扫码输入框旁边「📷 识别」→「拍照识别产品」或「拍照读文字」（脚本 `ui/recog_ui.js` + `ui/m_recog.js`，
  `modules/mobile/ui/m.html` 里加载；认出来的码 `SCAN.feed(码, "photo")`）。
- **电脑 / 平板网页**（`ui/desk.js`）：打包核对（`#pk-code`）、发货交接（`#ho-code`，读面单）、货位（`#loc-scan`）、移库（`#mv-scan`，读货位牌）、
  盘点「多出来的物品编码」（`[data-add]`，只填不回车）、采购到货（`#rc-scan`）、料卷（`#sp-scan`，读字）的扫码框旁边「📷」，认出来的码填进去、模拟回车。
  手机页 /m 所有页面（含 v2.52 的上架 / 移库）用的是同一个扫码栏，都有「📷 识别」。
- **安卓 App 的摄像头小窗**（App 1.1）：ML Kit 同时认文字，像码的文字（正则来自 `GET /api/mobile/code-patterns`，网页登录后 `Android3D.setTextPatterns(json)` 交给 App）
  连续 2 帧读到就 `onNativeScan(文字, "text")`；网页（`scan.js` / `desk.js`）先问 `/api/recog/text` 认成系统里的码（小标「文字」）。条码照旧。
- **系统 → 识别测试**（`ui/page.js`）：上传一批实物照片（文件名用 SKU 开头就知道正确答案）看认得准不准、一键「设为参考图」；拍照读文字测试；
  参考图状态、AI 用量。设置 → 组件与插件 里也有一张卡片。

- **参考照片管理**（1.1）：识别测试页「员工确认过的参考照片」、商品 360 抽屉最后一块（老板 / 上架）：看每张照片、删掉存错的、「改 SKU」挪到正确的 SKU，参考图马上重算。
  手机结果页选完 10 秒内有「选错了，撤销」：删掉刚存的参考照片、重新打开结果让员工重选（员工只能撤销自己 10 分钟内的；页面上已经记的要在页面上改）。
- **认不准的颜色**（1.1）：前 3 里有随机色 / 多色 / 彩虹 / 透明的规格时，结果页提示「颜色不可靠，请对一下实物」，并且不自动用第一个（AI 选的也不）。

## 拍照找产品怎么做（NAS 上不用显卡）

1. **参考图**（`refs.py`，每个产品一个 `data/recog/refs/<编号>.npz`，产品 / 模型 / 颜色表变了自动重算；开机后台补建，「重新生成识别图」手动全部重算）：
   - 产品图（`data/products/<编号>/out|raw`），按图片的颜色 / 规格的图片对到 SKU；
   - 3D 模型从 17 个角度画（`render.py`：画家算法 + Pillow，面多先精简到 1.5 万面），每个颜色规格上一次色（颜色表的颜色）；
     随机色 / 多色的规格画灰色、比对时颜色不算分；
   - 员工确认过的照片（`data/recog/learned/<编号>/`，每个 SKU 最多 24 张）。
2. **第一步：本地比特征**（`descriptor.py`，一张图 ≈ 0.1~0.4 秒）：
   - 抠出产品：有小的抠图模型（u2netp，4.6 MB，onnxruntime，设置卡片里「下载」）就用它，没有就按「画面边上的颜色是背景」估；
     手拿着拍时连到边上的肤色当背景；照片同时算好几种假设（模型抠图 / 边缘颜色抠图 / 白平衡校正），每张参考图取最像的；
   - 特征：颜色（色相直方图 + 白灰黑明暗）、形状（轮廓的极坐标分格 + 傅里叶幅度，转多少度都一样）、Hu 矩、内部边缘；
   - 每个 SKU 取最像的那张参考图，前 8 个候选；把握 = 分数高低 + 和第二名拉开多少。
3. **第二步：AI 看图挑**（`match.ai_pick`，可选）：照片 + 8 个候选拼成一张图（左边照片，右边编号 1~8），用 ERP 的 AI 接口（`core/ai_copy._request`，
   不让它在看不了图时悄悄退回纯文字）问「是哪一个、多大把握」。AI 不能看图（DeepSeek）、设置关了、当天次数用完、出错 → 只用第一步。
   每次拍照 = 1 次 AI 调用（一张约 1500×520 的图 + 约 300 字提示，约 1.5 千 token）。
4. **结果**：前 3 个（图、SKU、名称、颜色、把握）。把握 ≥ 设置的线（默认 0.75）并且没有平手 → 第一个高亮「是这个吗？」；否则提示「把握不够」让员工点。
   「都不是」→ 输入搜索（SKU / 名称 / 泰文标题）。点了哪个都记下来（`recog_log`），照片存成那个 SKU 的参考图（设置可关）。

**准确率**（`tests/eval_recog.py`，程序生成的 19 个产品 / 34 个 SKU、每种变化每个 SKU 3 张模拟手机照片，共 1326 张）：
有抠图模型时第一步前 1 79%、前 3 93%、前 8 98%（所有变化同时加的最难一组：48% / 75% / 89%）；没有抠图模型 63% / 78% / 90%。
同形状不同颜色基本分得开（认错里只有 5% 是「产品对、颜色错」）；同颜色、形状也像的（绿色圆环 / 绿色钥匙扣、黑色 L 支架 / 黑色手机支架、
白色的几个方块和杯子）会混——交给 AI 或员工从前 3 个里点。把握线 0.75 时约一半照片直接用第一个（那时 98% 是对的），其余让员工点（87% 正确答案在前 3）。
**局限**：真实照片没有测过（只有测试数据里浏览器画的 5 张场景图）；产品图本身是场景图、很多产品长得一样、反光 / 透明 / 多色的产品会差；
3D 模型画的颜色是颜色表的颜色，和真实耗材有差别（评估里模拟了）。上线后用「识别测试」页拍真实产品看，确认过的照片会让它越来越准。

## 拍照读文字（`ocr.py` + `textmatch.py`）

- 条码：zxing-cpp（已经在 requirements 里）在照片里找条码。
- 文字：本地 OCR（装了 `rapidocr_onnxruntime` 或系统有 `tesseract` 命令就用，不花钱），没有就用 AI 看图读字（设置可关）。
- **容错认码**（`textmatch.match`，App 的 ML Kit、拍照读字、`/api/mobile/resolve?fuzzy=1` 共用）：把文字切词、相邻 2~3 个词拼起来，
  算「骨架」（大写、去符号、O/Q/D→0、I/L/|→1、S→5、B→8、Z→2、G→6）和系统里的货位 / 货架 / 物品编码 / SKU / 最近 120 天的订单号和快递单号比：
  一样 1.0、骨架一样 0.93、包含 0.9、长码差 1~2 个字 0.85→0.6；前两个一样像时都降到 0.7（不自动用，让人点）；
  货位编号系统里没有也按格式整理（`a1 2 3` → `A1-02-03`，0.55，不自动用）。货架名（中文 / 泰文）也认。
- 手机 App 的正则（`textmatch.patterns`）：货位、按 SKU 前缀的 SKU、按系统里已有单号 / SKU / 物品编码的「样子」自动生成的正则、泰国常见快递单号；
  都要求至少 2 个数字（普通单词不送）。

## 接口

| 接口 | 说明 | 生产角色 |
|---|---|---|
| `POST /api/recog/identify`（photo, src, ai） | 拍照找产品 → `{rid, candidates[{sku, product_id, name_zh, title_th, opt1_zh, img, score, conf, ai?, via}], need_pick, ai{used, ok, pick, confidence, reason, why}, ms}` | ✓ |
| `POST /api/recog/confirm` `{rid, sku}` | 员工选了哪个（sku 空 = 都不是）；照片存成参考图（同一次再确认会先删掉上次存的） | ✓ |
| `POST /api/recog/unconfirm` `{rid}` | 撤销刚才的确认（员工：自己 10 分钟内的） | ✓ |
| `GET /api/recog/learned?q=SKU或产品编号` / `GET /api/recog/learned/<编号>/<文件>` | 员工确认过的参考照片 | ✗ |
| `POST /api/recog/learned/delete` `{pid, file}` / `.../move` `{pid, file, sku}` | 删掉 / 改到正确的 SKU（参考图重算） | ✗ |
| `GET /api/recog/search?q=` | 「都不是」手动搜 | ✓ |
| `GET /api/recog/text?q=&types=` | 文字 → 系统里的码 `{candidates, best}` | ✓ |
| `POST /api/recog/ocr`（photo） | 拍照读文字 `{barcodes, lines, engine, candidates, best}` | ✓ |
| `GET /api/recog/status` | 开关、AI 能不能用；老板 / 上架另外有参考图状态和用量 | ✓ |
| `POST /api/recog/build` `{force, pids}` | 后台（重新）生成参考图 | ✗ |
| `POST /api/recog/test`（photo, truth） | 识别测试（文件名 SKU 开头自动当正确答案） | ✗ |
| `POST /api/recog/model/download` | 下载抠图小模型（校验 sha256） | 只有老板 |
| `GET /api/mobile/code-patterns` | App 用的正则（mobile 模块，拍照识别关着时给空表） | ✓ |

对外（`modules.public("recog")`）：`match_text(文字)`、`code_patterns()`。

## 设置（组件与插件 → 拍照识别）

开关；AI 看图 auto / on / off；AI 每天最多几次（默认 300）；把握线（默认 0.75）；确认的照片存成参考图；没有本地 OCR 时用 AI 读字。

## 评估（`tests/eval_recog.py`、`tests/eval_ocr.py`，不在 run_all 里，跑一次几分钟）

    python modules/recog/tests/eval_recog.py --n 3 --download                 # 用设置卡片的接口下载抠图模型（--model 文件 也行；都不带 = 没有模型）
    python modules/recog/tests/eval_ocr.py --n 40                             # 装了 rapidocr 才测真的 OCR

装了 onnxruntime + 下载的 u2netp + rapidocr_onnxruntime（pip）时的结果（1326 张模拟照片）：前 1 79%、前 3 93%、前 8 98%（全部变化一起：48 / 75 / 89%）；
文字容错 800 条 98% 第一个对、自动用错 0；rapidocr 真读 104 张标签图（8 种字体、±20°、模糊、反光、暗、小字、坏条码）100% 认对，每张 0.6~1 秒。
